# SendFlow — сборка обновления

## Статус

Реализованы изменения исходников, новый Mini App, миграции и автоматические тесты. Это **кандидат для тестового развёртывания**, а не подтверждение работы с реальными Telegram-аккаунтами. Рабочий бот, аккаунты, платежи, домен и хостинг в этой сессии не подключались. Нет гарантии отсутствия ошибок, ограничений Telegram или взлома сервера.

## Что добавлено

- Обязательная подпись `Отправлено с помощью @SendFlowTgBot` после одной пустой строки: текст, фото, видео, копируемый пост, каждый вариант и автоответ. Истинная пересылка заменена копированием поддерживаемого содержимого.
- 4 дня полного PRO. Те же продуктовые права у активного trial, платной подписки и реферального бонуса. AI требует настройки провайдера. Технические ограничения остаются для всех.
- Активным подпискам с `source=trial` при первом запуске этой версии добавляется один день. Миграция отмечается в `schema_updates` и повторно день не добавляет. Истёкшие пробные периоды не перезапускаются.
- Текст + до 3 дополнительных вариантов; форматирование, медиа из чата, копирование одиночного поста по ссылке. Кнопки пользовательского аккаунта отображаются как ссылки в тексте.
- Предпросмотр фактических получателей с привязкой папки к конкретному аккаунту, тест в Избранное, выбор аккаунтов в Mini App, исключение личных диалогов и защита от дублей между аккаунтами.
- Расписание в Mini App и в чате (в том числе фото/видео): один раз, ежедневно, по дням недели. Часовой пояс IANA, проверка неоднозначных и отсутствующих локальных времён при переводе часов.
- В Mini App → Аккаунты → Настройки: уведомления об ответах на сообщения рассылки; уведомления о личных сообщениях; автоответ всегда или вне рабочих часов. Не чаще одного автоответа человеку за 24 часа. Ботам и себе не отвечает. Автоответ и уведомления о личных сообщениях по умолчанию выключены.
- В уведомлении — автор, маскированный аккаунт, цитата, исходный текст рассылки и кнопка. В группах — ссылка на ответ при наличии доступа; в личных диалогах — диалог или профиль. Нужно переключиться в соответствующий аккаунт Telegram. Для обычных старых групп точная ссылка может отсутствовать.
- Новая вкладка PRO с реальной ценой, сроком и лимитами. Реальная статистика вместо искусственных прибавок.
- Атомарные реферальные бонусы: только новый пользователь, существующий пригласивший, без самоприглашений и повторного начисления. Бонус не сокращает активную подписку и не заменяет источник активного платного/trial-периода.
- Уникальная квитанция Stars, проверка суммы/валюты/payload, выдача подписки и запись платежа в одной транзакции.
- Шифрование сессий, API hash и прокси отдельным ключом; проверка владельца задания, возраста initData, ограничение запросов, короткоживущий токен Mini App. Frontend отправляет данные только на собственный origin, не на адрес из URL-параметра.
- Один постоянный Telegram-клиент на аккаунт; фоновые уведомления продолжаются после рассылки. Повторный вход в терминале сервера не запускается.
- Пауза и прогресс сохраняются. Подтверждённые и неопределённые отправки после сбоя не повторяются автоматически. Если произошёл сбой между отправкой и сохранением результата, сообщение может оказаться доставленным без подтверждения в отчёте: гарантия exactly-once не заявляется.

## Что намеренно отключено / ограничено

- Скрытые упоминания и автоматические вступления не доступны через пользовательские сценарии. Бот не скрывает новые каналы в архиве. В исходниках сохранена часть старых внутренних помощников для совместимости, но новые запуски не включают эти возможности.
- Защищённые посты, альбомы и неподдерживаемые типы по ссылке не копируются. Встроенные callback-кнопки чужих ботов не переносятся; поддерживаются URL-ссылки.
- По умолчанию до 5 аккаунтов, 50 папок, 5 параллельных заданий пользователя, 999 циклов в задаче, 50 активных расписаний. Один аккаунт не запускается одновременно в двух рассылках.
- По режиму «Все чаты» выбираются группы/супергруппы. Канал можно выбрать в явной папке, при этом проверяются права публикации.
- История динамических папок Telegram, составленных только флагами (например «все группы»), не разворачивается автоматически: для папок используются явно добавленные/закреплённые чаты. Всегда проверяйте предпросмотр.
- Расписание хранит снимок получателей. Новые участники папок не добавляются к уже сохранённой задаче. Отредактировать дату/часовой пояс можно в Mini App; для изменения содержания/дней/аккаунтов отмените расписание и создайте новое.
- Допуск запуска таймера — 2 минуты. Более старое событие приостанавливается и требует ручного переноса. Долгое ограничение Telegram может сдвигать фактические отправки; время — момент запуска задачи, а не обещание доставки всем в одну секунду.
- Автоочистка журналов и служебных записей по сроку **не включена**: на её добавление запрошено отдельное разрешение. Автоматического удаления старых платежей/подписок нет. Размер БД нужно контролировать.
- Содержимое входящих сообщений не сохраняется в PostgreSQL, но попадает в чат с ботом при включённых уведомлениях. Метаданные событий, короткие фрагменты исходящих сообщений и журналы сохраняются без автоматического срока удаления в этой сборке. Не обещайте пользователям полное отсутствие хранения данных.

## Перед обновлением действующего сервиса

1. Остановите старый процесс. Не запускайте старую и новую версии одновременно.
2. Сделайте резервную копию PostgreSQL и постоянного диска с медиа. Храните её отдельно от ключа шифрования.
3. Сначала установите обновление на **копию** БД, не на единственную рабочую базу.
4. Сохраните прежние переменные окружения. Старые встроенные API-реквизиты и ID администратора удалены из кода; явно задайте свои `ADMIN_IDS`, `DEFAULT_API_ID`, `DEFAULT_API_HASH`.
5. Проверьте часовой пояс прежнего сервера. Раньше сроки подписки записывались без смещения через `datetime.now()`. Новая сборка использует UTC. Если прежние значения были местным временем другого пояса, администратор должен предварительно привести сроки к UTC на копии БД. Автоматически угадать старый пояс нельзя.
6. Задайте новый ключ шифрования, установите зависимости, запустите новую сборку. Схема и шифрование существующих строк мигрируют при старте. Нужны права CREATE/ALTER и запись данных.
7. Старые незавершённые задания без снимка получателей останавливаются: их нужно заново проверить и запустить. Новые задания этой версии восстанавливаются по журналу отправок.
8. Не возвращайте старую версию на уже зашифрованную БД: она не умеет читать зашифрованные сессии. Для отката восстанавливайте **вместе** старый код и резервную копию до миграции.

## Установка

Поддерживается один процесс `python main.py` на одну БД. Процесс держит PostgreSQL advisory lock. Не запускайте webapp_server.py отдельно: у него нет общего состояния клиентов/уведомлений/оплаты с ботом. Не используйте несколько worker-реплик.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock.txt
cp .env.example .env
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Последняя команда выводит **ваш новый секретный ключ**: сохраните его в `SESSION_ENCRYPTION_KEYS` через защищённые настройки сервера, не отправляйте в чат и не коммитьте. Заполните `.env` / настройки хостинга своими значениями, затем:

```bash
python main.py
```

Обязательные переменные:

- `BOT_TOKEN` — токен именно вашего бота. Для подписи/анонса используется заданное имя @SendFlowTgBot; убедитесь, что развёрнут правильный бот.
- `DATABASE_URL` — PostgreSQL; в production используйте защищённое соединение с корректной проверкой сертификата (например Neon connection string). `sslmode=disable` допустим только для изолированных локальных тестов.
- `SESSION_ENCRYPTION_KEYS` — ключ Fernet; без него запуск завершается ошибкой. Потеря ключа означает потерю возможности читать сохранённые сессии. Резервируйте ключ отдельно от БД.
- `DEFAULT_API_ID`, `DEFAULT_API_HASH` — ваши Telegram API-реквизиты с my.telegram.org. Они нужны для входа через Mini App. Реквизиты приложения не заменяют пользовательский вход.
- `ADMIN_IDS` — ваши числовые Telegram ID, через запятую. По умолчанию чужих администраторов нет.
- `WEBAPP_URL` — точный публичный HTTPS origin приложения, например `https://your-app.example`. Интерфейс и API в этой сборке размещаются на одном origin.
- `DATA_DIR` — постоянный диск для медиа; на Amvera обычно `/data`. Без постоянного диска запланированные медиа могут стать недоступны после redeploy.
- `OWNER_CONTACT`, `OWNER_CONTACT_URL` — актуальный контакт поддержки/ручной оплаты.

`REQUIRED_CHANNEL`/`REQUIRED_CHANNEL_URL`: ваш канал, бот должен иметь права для проверки членства. Пустой `REQUIRED_CHANNEL` отключает обязательную подписку. Пробный период активируется через /trial или кнопку в PRO.

`AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL` — необязательны. При AI-обработке текст отправляется внешнему провайдеру; раскройте это в политике. После перезапуска проверьте, что ключи доступны процессу, а Mini App опубликован по правильному HTTPS адресу. Меню/кнопки бота используют `/static/index.html?v=4`.

Тариф: `SUB_PRICE_STARS`, `SUB_DAYS`, `PAID_MAX_ACCOUNTS`, `PAID_MAX_FOLDERS`, `MAX_CONCURRENT_JOBS`, `MIN_COOLDOWN`. Пробный период фиксированно 4 дня. Не меняйте цену/срок без проверки выставленных ранее счетов: pre-checkout принимает текущую цену/срок.

Смена ключа: добавьте новый первым в `SESSION_ENCRYPTION_KEYS=new,old`, перезапустите и проверьте копию БД. Стартовая миграция перешифрует строки новым ключом. Не удаляйте старый ключ из резервных копий ключей, пока нужны старые backup БД.

## Команды и управление

- `/start`, `/menu`, `/help`, `/trial`, `/privacy`, `/stats`.
- `/recipients` — полный текстовый файл списка перед отправкой.
- `/testsend` — тест подготовленного сообщения в Избранное первого аккаунта. Другой аккаунт можно выбрать в Mini App.
- `/stopall` — остановить текущие рассылки. **Не отменяет будущие расписания**: они отменяются отдельно в Mini App → Мониторинг.
- В чате после предпросмотра «Запланировать отправку»: дата/время/пояс, затем один раз / ежедневно / дни недели.
- Аккаунты → Удалить: остановка задач, попытка log_out, удаление данных после подтверждения. При сетевой ошибке строка остаётся с `revoke_failed` для повторной попытки и не используется фоновыми слушателями. Если Telegram уже отозвал ключ, повторное удаление завершает очистку записи.

## Проверка перед публичным запуском

Подробности в TEST_REPORT.md. Автотесты не заменяют пункты ниже:

- Вход в реальный рабочий тестовый аккаунт: код, 2FA, неправильный код, истечение кода, повторное нажатие, отмена.
- Два тестовых аккаунта, разные папки с одинаковыми внутренними ID и одинаковыми названиями. Проверить содержимое предпросмотра.
- Отправка в собственную тестовую группу/канал: текст, варианты, фото, видео, копирование доступного поста, ссылки, подпись.
- Ответ другого человека на отправленное сообщение; ссылка из уведомления. Личное сообщение, автоответ, рабочие часы, отключение функций.
- Расписание: ближайшее время, повтор, перезапуск, длительное выключение сервера, истечение PRO.
- Реальная небольшая оплата Stars и проверка единственного начисления. Проверьте поддержку платежей и процедуру возврата до публикации.
- Отзыв доступа и список «Устройства» в Telegram. Удалённый аккаунт не должен отправлять дальше.
- Восстановление БД и ключа из резервной копии, ограничение доступа к БД, мониторинг объёма журналов и доступности процесса.

Публикуйте CHANNEL_POST.md только после развёртывания и этих проверок. Текст не утверждает, что бот уже был опубликован из этой среды.
