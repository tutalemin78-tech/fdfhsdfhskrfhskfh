# Проверки сборки SendFlow

## Подтверждено локально

Среда: Linux, Python 3.13, PostgreSQL 15 (изолированный экземпляр на localhost, отдельная UTF-8 БД `sendflow_test`). Внешние Telegram-аккаунты не подключались. Вызовы Telegram в тестах заменены имитациями, платежи — тестовыми объектами.

**Итог: 65 автоматических тестов прошли, 0 ошибок.** 9 предупреждений тестового окружения не являлись ошибками. Исходники проверены `compileall`; `pyflakes` не сообщил ошибок или предупреждений в файлах верхнего уровня. JavaScript проверен `node --check`; повторяющихся HTML ID не обнаружено.

Проверены:

- подпись initData, срок действия, даты из будущего, изменение содержимого и дубли полей;
- подпись/истечение серверного токена, невозможность бесконечно продлевать его без свежего initData;
- шифрование сессии и ключевая ротация; отказ при отсутствии ключа;
- ровно одна подпись под текстом, фото, видео и копируемым постом, лимиты UTF-16 и текст URL-кнопок;
- исключение личных получателей и привязка папок к аккаунтам;
- рассылка двумя имитированными аккаунтами и пропуск общей группы при включённой дедупликации;
- повторное восстановление одного задания без повторной отправки, неопределённые отправки и сохранённая пауза;
- отказ в запуске с занятого аккаунта и без активной подписки;
- чужой пользователь не читает/не меняет задание и настройки аккаунта через API;
- серверный одноразовый предпросмотр, невозможность подставить свои targets вместо него;
- цитирование/экранирование ответа, ссылка на групповое сообщение, отсутствие повторного уведомления;
- уведомления о личных сообщениях, автоответ один раз за 24 часа, рабочие часы, истёкшая подписка;
- отзыв сессии перед удалением, сохранение остановленной записи при неудаче отзыва, удаление уже отозванной сессии;
- отсутствие интерактивного повторного входа в серверном Telegram-клиенте;
- пробный период 4 дня, одноразовая и конкурентная активация, доступ PRO;
- однократная миграция активного trial с добавлением суток;
- конкурентные реферальные начисления, запрет приглашения себя/старого пользователя, сохранение активного тарифа;
- атомарное продление подписок и уникальная обработка квитанции Stars;
- проверка pre-checkout, суммы/валюты/payload;
- атомарные ограничения числа аккаунтов и серверный лимит шаблонов;
- сохранение расписаний, владельцы, отмена/перенос, запуск наступившей задачи и пауза пропущенной;
- переход часов Europe/Berlin: отсутствующее/неоднозначное время, сохранение местного времени ежедневного повтора;
- создание расписания для медиа через чат бота.

## Проверка интерфейса

Chromium + Playwright, мобильное окно 390×844 и широкое 1280×900. HTML нового пользовательского Mini App, API имитирован локально; внешние запросы заблокированы.

Проверены открытие, предпросмотр получателей, подтверждение запуска, настройки уведомлений и автоответа, недельное расписание, цена и срок PRO. В этих сценариях не зафиксированы ошибки JavaScript и горизонтальное переполнение мобильного экрана.

Браузерные тесты находятся в `tests/ui_smoke.cjs`. Они проверяют интерфейс, а не реальную доставку Telegram. Для повторения установите Playwright в отдельном dev-окружении и укажите CHROMIUM_PATH к локальному Chromium.

## Как повторить Python-тесты

Тесты очищают таблицы **только в явно указанной одноразовой локальной БД**. Не используйте рабочую БД или её единственную копию.

```bash
pip install -r requirements-test.txt
# Предварительно создайте локальную пустую БД sendflow_test с кодировкой UTF-8.
# Подставьте свою локальную роль PostgreSQL:
TEST_DATABASE_URL='postgresql://YOUR_LOCAL_ROLE@127.0.0.1:5432/sendflow_test?sslmode=disable' python -m pytest -q
```

В тестах используются заведомо фиктивные BOT_TOKEN, API hash и ключ Fernet из conftest.py. Они не предназначены для сервера. Fixture требует локальный адрес и имя sendflow_test.

## Не проверено вживую — обязательный этап перед публикацией

1. Telegram-вход, доставка кодов и 2FA, лимиты авторизации и текущая совместимость Pyrogram с Telegram.
2. Доставка текста/медиа/копируемых постов, реальные permissions, FloodWait и ограничения Telegram.
3. Фоновые updates, получение ответов и личных сообщений с нескольких реальных аккаунтов, корректность ссылок в клиенте пользователя.
4. Реальная Stars-оплата, задержка successful_payment, поддержка оплаты и возвраты.
5. Production-домен, HTTPS/reverse proxy, права бота в обязательном канале.
6. Хостинг и его целевая версия Python (исходная конфигурация Amvera указывает 3.11; локальный прогон сделан на 3.13).
7. Нагрузочный тест большого числа аккаунтов, долгий простой, восстановление backup, наблюдаемость сервиса.
8. Перенос сроков старой БД в UTC, если старый сервер использовал иной часовой пояс.

Эта проверка не является независимым аудитом безопасности, доказательством соответствия правилам Telegram или гарантией отсутствия багов. Сессия остаётся доступом к аккаунту; шифрование не устраняет риск компрометации работающего сервера.

## Отдельное неподтверждённое изменение

Автоматическое удаление журналов/служебных данных старше 30 дней **не добавлено**. На него запрошено отдельное согласие; текущая сборка не включает такую автоочистку.
